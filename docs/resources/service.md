# truenas_service (Resource)

Manages the state of a built-in TrueNAS system service, such as NFS or SMB. Services are part of the appliance and are never created or removed: this resource only takes ownership of an existing service's boot and run state. Destroying the resource therefore stops the service and disables it at boot.

~> **Destroying this resource stops the service and disables it at boot.** TrueNAS system services are part of the appliance: they cannot be created or deleted, only turned on and off. Terraform therefore treats `terraform destroy` — and any change that forces replacement — as "give the service back", which means stopping it and clearing its start-on-boot flag. Anything relying on that service goes offline. This is the same posture other providers take for resources that configure something they did not create.

## Example Usage

### Enable and Start a Service

```terraform
# Turn on NFS so the shares below can be mounted
resource "truenas_service" "nfs" {
  name = "nfs"
}

resource "truenas_dataset" "media" {
  pool = "tank"
  path = "media"
}

resource "truenas_share_nfs" "media" {
  path    = truenas_dataset.media.full_path
  comment = "Media library"

  depends_on = [truenas_service.nfs]
}
```

### Enable at Boot Without Starting Now

```terraform
resource "truenas_service" "smb" {
  name    = "cifs"
  enable  = true
  running = false
}
```

### Run a Service Without Enabling It at Boot

```terraform
resource "truenas_service" "ssh" {
  name    = "ssh"
  enable  = false
  running = true
}
```

> **Note:** Manage each service with at most one `truenas_service` resource. Two resources naming the same service fight over its state on every apply.

> **Note:** `name` is the service's API name, which is not always its display name — SMB is `cifs` and iSCSI is `iscsitarget`. The available names depend on the TrueNAS version and edition; applying an unknown name fails with the list the appliance does offer.

> **Note:** Changing `name` replaces the resource, which stops and disables the old service before adopting the new one.

## Import

Services are imported by name:

```shell
terraform import truenas_service.nfs nfs
```

Importing adopts the service as it is; the following `terraform apply` brings it to the configured `enable` and `running` state.

## Schema

### Required

- `name` (String) Name of the service to manage, as reported by the `service` API namespace — for example `nfs`, `cifs`, `ssh` or `iscsitarget`. The set of services depends on the TrueNAS version and edition; an unknown name fails with the list the appliance does offer.

### Optional

- `enable` (Boolean) Start the service automatically on boot.
- `running` (Boolean) Run the service now. Terraform starts or stops the service to match this value, and reports it back from the server so an out-of-band stop shows up as drift.

### Read-Only

- `id` (String) Service name, which is also the identifier used for import.
