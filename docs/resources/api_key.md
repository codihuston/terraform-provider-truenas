# truenas_api_key (Resource)

Manages an API key for a TrueNAS user account. TrueNAS discloses the key secret only in the reply that creates it and never reads it back, so `key` is null for an imported key, and for one created with `store_key = false` once it has been refreshed.

## Example Usage

### Basic API Key

```terraform
# Issue an API key for a service account and hand it to a consumer
resource "truenas_api_key" "backup" {
  name     = "backup-agent"
  username = "backup"

  expires_at = "2035-01-02T15:04:05Z"
}

output "backup_api_key" {
  value     = truenas_api_key.backup.key
  sensitive = true
}
```

### Passing the Key to Another Provider Without Storing It

Set `store_key = false` to keep the secret out of Terraform state. The value is
readable only by resources and providers evaluated in the **same apply that
creates the key**; from the next refresh onwards `key` reads as `null` and
nothing can recover it.

```terraform
resource "truenas_api_key" "bootstrap" {
  name      = "bootstrap"
  username  = "truenas_admin"
  store_key = false
}

# Consumed in the same apply that creates the key.
resource "vault_kv_secret_v2" "truenas" {
  mount = "kv"
  name  = "truenas/bootstrap"

  data_json = jsonencode({
    api_key = truenas_api_key.bootstrap.key
  })
}
```

> **Note:** TrueNAS returns the key secret **only** in the reply that creates it. It is never readable again, so `key` is `null` for an imported key, and for any key created with `store_key = false` once its first refresh has run.

> **Note:** Because the secret can only be captured at creation, changing `store_key` from `false` to `true` destroys and recreates the key. Anything still using the old secret stops authenticating.

> **Note:** For a key created with `store_key = false`, `store_key` must be known at plan time. Terraform cannot decide whether storing the key again requires issuing a new one while the value is unknown, so planning fails with an error.

> **Note:** `username` cannot be changed on an existing key. Changing it destroys and recreates the key.

> **Note:** TrueNAS revokes keys on its own, for instance once `expires_at` passes. Such a key still exists and stays in state, with `revoked` set to `true` and `revoked_reason` explaining why.

## Import

API keys can be imported using the numeric key ID:

```shell
terraform import truenas_api_key.example 1
```

The secret is not part of an import: `key` reads as `null` on an imported key.

## Schema

### Required

- `name` (String) Human-readable name for the API key. Must be unique.
- `username` (String) Username the key authenticates as. Changing this forces a new API key, because TrueNAS cannot reassign an existing key to another account.

### Optional

- `expires_at` (String) RFC 3339 timestamp at which the key stops authenticating, for example `2035-01-02T15:04:05Z`. Omit for a key that never expires.
- `store_key` (Boolean) Whether to persist `key` in Terraform state. When `false`, the secret is readable only by resources in the same apply that creates the key, and is dropped from state on the next refresh; nothing can recover it afterwards. Setting this back to `true` forces a new API key, since that is the only way to obtain a secret. For a key created with `store_key` set to `false`, this value must be known at plan time.

### Read-Only

- `created_at` (String) RFC 3339 timestamp, in UTC, at which the key was created.
- `id` (String) API key ID.
- `key` (String, Sensitive) The API key secret, in the `<id>-<token>` form TrueNAS clients expect. Null unless this resource created the key with `store_key` set to `true`.
- `local` (Boolean) Whether the key belongs to a local account rather than a directory account.
- `revoked` (Boolean) Whether the key has been revoked and no longer authenticates. TrueNAS revokes keys on its own, for example once they expire.
- `revoked_reason` (String) Why TrueNAS revoked the key, or null while it is still valid.
- `user_identifier` (String) UID of the local account, or SID of the directory account, that owns the key.
