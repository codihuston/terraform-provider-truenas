# truenas_user (Resource)

Manages a local user account. Accounts are created without password authentication unless `password` is supplied, so the default account authenticates by SSH key or not at all.

## Example Usage

```terraform
resource "truenas_group" "developers" {
  name = "developers"
}

# A service account that authenticates with an SSH key and has no password
resource "truenas_user" "deploy" {
  username  = "deploy"
  full_name = "Deployment Account"

  group  = truenas_group.developers.id
  groups = [truenas_group.developers.id]

  home        = "/mnt/tank/home"
  home_create = true
  shell       = "/usr/bin/bash"

  password_disabled = true
  ssh_public_key    = file("${path.module}/deploy.pub")

  sudo_commands_nopasswd = [
    "/usr/bin/systemctl restart myapp",
  ]
}

# An account with its own primary group, created and deleted alongside the user
resource "truenas_user" "alice" {
  username  = "alice"
  full_name = "Alice Example"

  group_create      = true
  shell             = "/usr/bin/zsh"
  password_disabled = true
}
```

## Authentication

Accounts are created without a password unless `password` is set, so the default
account authenticates with an SSH key or not at all. Set `password_disabled` to
make that explicit and to reject password authentication outright.

TrueNAS writes `ssh_public_key` into the account's home directory, so a key-only
account needs a writable home. `home` defaults to `/var/empty`, which is not
writable; set `home` and `home_create` to have TrueNAS create one.

`smb` is disabled by default. TrueNAS requires password authentication for SMB
users and adds them to the `builtin_users` group, neither of which suits a
key-only account. Enabling `smb` therefore requires `password` and forbids
`password_disabled`.

## Passwords

`password` is a [write-only attribute][write-only]: Terraform sends it to
TrueNAS but never writes it to state, and TrueNAS never returns it. A password
changed outside Terraform produces **no drift**, and there is no way for the
provider to detect one.

Because there is nothing in state to compare against, changing the value in the
configuration is not enough to re-send it. Increment `password_wo_version` to
send the current `password` on the next apply:

```terraform
resource "truenas_user" "support" {
  username  = "support"
  full_name = "Support Account"

  group_create = true

  password            = var.support_password
  password_wo_version = 2
}
```

Write-only attributes require Terraform 1.11 or later.

[write-only]: https://developer.hashicorp.com/terraform/language/resources/ephemeral/write-only

## Home directories

When `home_create` is set, TrueNAS creates the home directory at
`<home>/<username>` rather than at `home` itself. `home` is therefore the parent
directory, and the path TrueNAS actually assigned is exported as `home_path`.

`home_create` is only sent when `home` changes. While `home` stays put the
provider sends `home_path` instead, because TrueNAS accepts a parent directory
only when creating a home and rejects it on a later update.

`home`, `home_create` and `home_mode` are inputs TrueNAS does not report back.
Changes made to them outside Terraform are not detected, and after an import they
hold their default values rather than the account's real configuration.

## Group membership

`group` and `groups` take group *entry IDs*, as exported by
`truenas_group.<name>.id`, not Unix GIDs.

Leave `groups` unset to let TrueNAS manage supplementary membership, which is
what happens when `smb` adds the account to `builtin_users`. Set it to `[]` to
remove all supplementary groups.

## Import

Users can be imported using the user entry ID:

```shell
terraform import truenas_user.deploy 71
```

## Schema

### Required

- `full_name` (String) Descriptive name for the account, such as the person's full name or the purpose of a service account.
- `username` (String) Login name. Limited to alphanumerics, hyphens, underscores and periods, and may not begin with a hyphen or a period.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `delete_group` (Boolean) Delete the primary group along with the user, provided no other user depends on it. Set this to `false` when the primary group is managed by a separate `truenas_group` resource.
- `email` (String) Email address for the account. Accounts with the `FULL_ADMIN` role receive alerts and notifications at this address.
- `group` (Number) Entry ID of the primary group, as exported by `truenas_group.<name>.id`. This is the group entry ID, not the Unix GID. Required unless `group_create` is set.
- `group_create` (Boolean) Create a new group named after the user and use it as the primary group. Only honoured when the user is created; TrueNAS rejects it on update.
- `groups` (Set of Number) Entry IDs of additional groups the user belongs to. Leave unset to let TrueNAS manage membership, which is what happens when `smb` is enabled and the user is added to `builtin_users`. Set to `[]` to remove all additional groups.
- `home` (String) Home directory to assign to the user. When `home_create` is set this is the parent directory and TrueNAS creates the home at `<home>/<username>`; the resulting path is exported as `home_path`.
- `home_create` (Boolean) Create the home directory under `home`. Only sent when `home` changes, so repeated applies do not move or nest the existing home.
- `home_mode` (String) Octal permissions applied to the home directory. TrueNAS does not report this back, so changes made outside Terraform are not detected.
- `locked` (Boolean) Lock the account so it cannot authenticate.
- `password` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Password for the account. This is a write-only attribute: it is never written to state and never read back, so a password changed outside Terraform produces no drift. Increment `password_wo_version` to send it again.
- `password_disabled` (Boolean) Disable password authentication. The account can still authenticate by other means, such as an SSH key. Cannot be combined with `smb`.
- `password_wo_version` (Number) Change this value to re-send `password` on the next apply. Because `password` is write-only, this is the only way to trigger a password change.
- `shell` (String) Login shell. Valid choices come from the `user.shell_choices` API method, for example `/usr/bin/bash` or `/usr/sbin/nologin`.
- `smb` (Boolean) Allow the account to access SMB shares. TrueNAS requires a password for SMB users and adds them to `builtin_users`, so this defaults to disabled.
- `ssh_password_enabled` (Boolean) Allow SSH password authentication. Leave disabled and use `ssh_public_key` unless password logins are specifically required.
- `ssh_public_key` (String) SSH public keys authorised for this account. TrueNAS writes these to the user's home directory, so `home` must point at a writable path.
- `sudo_commands` (List of String) Commands the user may run with elevated privileges, prompting for a password.
- `sudo_commands_nopasswd` (List of String) Commands the user may run with elevated privileges without a password prompt.
- `uid` (Number) Unix user ID. Defaults to the next available UID. Changing this forces a new user.

### Read-Only

- `builtin` (Boolean) Whether the account is built in to TrueNAS.
- `home_path` (String) Home directory TrueNAS assigned to the user.
- `id` (String) User entry ID.
