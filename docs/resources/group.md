# truenas_group (Resource)

Manages a local group. Use the group's `id` for the `group` and `groups` attributes of `truenas_user`, which take group entry IDs rather than Unix GIDs.

## Example Usage

```terraform
# A group to share ownership of a project directory
resource "truenas_group" "developers" {
  name = "developers"
}

# A group whose members may restart one service without a password prompt
resource "truenas_group" "operators" {
  name = "operators"

  sudo_commands_nopasswd = [
    "/usr/bin/systemctl restart myapp",
  ]
}
```

## Group IDs

TrueNAS distinguishes the group *entry ID* from the Unix *GID*. The `id` attribute
is the entry ID, and it is what `truenas_user` expects in its `group` and `groups`
attributes. The `gid` attribute is the Unix GID that appears on the file system.

Membership is managed from the user side, through `truenas_user.groups`. This
resource does not manage the group's member list, so the two resources cannot
fight over it.

## Import

Groups can be imported using the group entry ID:

```shell
terraform import truenas_group.developers 110
```

## Schema

### Required

- `name` (String) Group name.

### Optional

- `gid` (Number) Unix group ID. Defaults to the next available GID. Changing this forces a new group.
- `smb` (Boolean) Allow the group to be used in SMB share ACL entries.
- `sudo_commands` (List of String) Commands group members may run with elevated privileges, prompting for a password.
- `sudo_commands_nopasswd` (List of String) Commands group members may run with elevated privileges without a password prompt.

### Read-Only

- `builtin` (Boolean) Whether the group is built in to TrueNAS.
- `id` (String) Group entry ID.
